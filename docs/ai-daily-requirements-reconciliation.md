## Public Signal Stream Contract

Status: `current-authority / implementation-in-progress`.

The user changed the controlling public product direction on 2026-07-14. The repository is a high-coverage AI source listener; the edited story report remains an optional legacy derivative and cannot govern public signal membership.

- No content-admission gate exists in the public occurrence path. A safe HTTP(S) material URL is sufficient for membership; missing title text uses a deterministic publisher/source/URL fallback, while a structurally unsafe individual record is isolated without blocking the rest.
- Credibility, content, source, health, and access metadata are labels and filters only. Editorial score, authority, verification, selection, rejection, quality, quotas, dedupe, and report status cannot change membership or default chronology.
- Same-URL observations remain distinct occurrences and share a `cluster_id` only for navigation.
- Unknown source, content, and credibility metadata falls back to `other` / `pending_review` instead of failing, hiding, or demoting the record.
- Public fields are reader-safe title, link, summary, publisher, collection channel, source group, content tags, credibility tag, event/publication/collection time, image, health, and access state. Candidate IDs, raw audit, scores, selection/rejection reasons, repair state, notes, and private paths remain internal.
- `config/public-signal-taxonomy.json`, `schemas/occurrence-store.schema.json`, and `schemas/public-signals.schema.json` are the public data authorities. `config/source-display-contract.json` remains an internal source-inventory governance contract only.
- PR1 owns the contract and projection, PR2 owns aggressive public/legal expansion plus production independence from the legacy editorial gate, and PR3 owns the complete scheme-C frontend migration and deletion of obsolete public pages.

The historical addenda below remain evidence for the legacy edited-report subsystem. They are not current public admission or IA rules.

## Story-Centered Contract Addendum (Historical Edited Report)

Status: `implemented / publish-run-validation-pending`.

The user confirmed on 2026-06-23 that the then-current edited-report target was story-centered, not raw source-item-centered. This remains implemented for that legacy derivative, but it was superseded as the controlling public product direction by the 2026-07-14 Public Signal Stream Contract.

- The main reader list is a set of edited, merged `stories`.
- Default story count is 8, maximum is 12, and fewer than 8 is acceptable when fewer qualified stories exist.
- The generator must not fill the main list with templated items such as `OpenAI更新AI 产品、平台或工程实践`.
- Strong primary single-source stories may enter the main list; secondary or community single-source items default to signal sections.
- Story merge and dedupe use factual identity and source URLs, not title or summary template similarity.
- Stories published in the previous 7 reports are excluded from the main list unless there is material new progress.
- GitHub Trending is a first-class fixed module: public Top10 items remain directly visible and are not folded into an appendix.
- Summary and trend clusters are derived from visible stories, GitHub Trending, or signal items, and must be able to link back to them.
- Quality gates should degrade by removing or demoting bad story candidates; they block only when publish artifacts are unusable, main stories are unverifiable, or publish safety fails.

The full contract, implementation surfaces, and staged TODO are in `docs/ai-daily-story-contract.md`. Schema, draft generation, report writing, rendering, page checklist, and regression tests are implemented in this branch. Do not claim a specific daily publish succeeded unless that date's run summary also proves `publish:dry-run:daily`, real publish or fallback, Pages verification, and blocking/degraded status.

## Source-First V2 Addendum (Historical 2026-06-30 Runtime Dashboard)

Status: `superseded-for-public-runtime / retained-as-internal-governance`.

The user confirmed on 2026-06-30 that the 2026-06-29 source-first runtime dashboard exposed excessive machine audit content. That decision still bans raw audit dashboards, but it no longer bans a reader-safe source-first occurrence stream. The 2026-07-14 contract makes source-first public again through safe cards and labels, not through machine logs.

- Public daily pages must not render `source_signal_story`, `source_first_dashboard`, `system_operating_dashboard`, `source_status_focus`, `source_map`, `source_inventory`, or their generated detail groups by default.
- The internal source-first runtime puts `source_signal_story` before `source_metrics_dashboard`.
- `source_signal_story` summarizes the day's effective, updated, blocked, stale, skipped, and empty source lanes only inside the internal diagnostic surface.
- `source_metrics_dashboard` follows the story and shows operational metrics, including effective source counts, blocked/stale/no-update counts, and section health, only inside the internal diagnostic surface.
- Source governance order is fixed editorial order, not a daily dynamic sort: `core_primary`, `china_models`, `open_source_platforms`, `tracking_metrics`, `builder_community`, `platform_cn_media`, then `english_media_search`.
- The source governance unit is `logical_source`. A logical source may group multiple collection entries when they represent the same named source identity.
- The complete inventory unit is `collection_entry`. The current 166 collection entries are internal inventory rows, not public occurrence cards.
- Full inventory expansion means every collection entry remains visible exactly once inside the internal source-first runtime, grouped by fixed section rank, with search or focus behavior that highlights but does not hide non-matching rows.
- Blocked, stale, skipped, unconfigured, disabled, manual, and no-update sources must remain visible to source governance rather than silently disappearing.
- Story-centered daily content remains an optional edited derivative; reader-safe occurrences are the public fact and lead carrier. Raw coverage, reliability, gaps, and operational provenance stay internal.
- `config/public-signal-taxonomy.json` is the executable public grouping/tag authority. `config/source-display-contract.json` governs the internal inventory, and `docs/source-first-ia-handbook.md` explains both layers.

## Generation Repair Addendum (Historical Legacy Edited Report)

The user confirmed this generation-side correction on 2026-06-15, when it became the controlling contract for the edited report. It is now retained only for that optional legacy derivative and was superseded as the public product contract by `public-signal-stream-contract:v1`. None of its authority weights, qualification rules, counts, refill logic, or report gates may remove or reorder a public occurrence.

- Legacy REQ-001 extension: the edited-report main list keeps a 5-item minimum, targets 8 items, and caps at 12 deduplicated stories. These bounds never apply to the public signal stream.
- Legacy REQ-002 extension: source authority becomes ranking weight inside the edited report, not a public occurrence admission gate. Legacy story selection uses explicit blacklist rejection, including `low_value_vendor_availability_pr` for third-party channel availability announcements that only restate another provider's model access.
- REQ-003 extension: draft generation must run a main-stream fill loop before writing the report; page checks remain tolerant fallback rather than the primary quality mechanism.
- REQ-004 extension: sparse main stream becomes a generation quality event with selected count, refill count, remaining shortfall, source impacts, and top rejection reasons.
- REQ-005 extension: official source coverage must be measured through source health records, not just source registry presence.
- Legacy REQ-006 to REQ-009 extension: GitHub Trending, Builder/X, hot blogs, GitHub watchlist, direct Chinese RSS, and community hotspot leads become role-tagged candidates for the optional edited report. Qualification and refill apply only there; every safely normalized observation is independently retained in the public signal stream.
- Candidate audit extension: every evaluated candidate must have either `main_selection_stage` or `main_reject_reason`, with duplicate, merge, source-health, and `window_fill` details where applicable. Public pages must hide these diagnostics.
- Source repair extension: page rendering may disclose degraded status, but source-health records and discovery fixes are the implementation authority. A source registered in config is not considered covered until it has recent checked/effective evidence or an explicit no-signal/blocked/unconfigured reason.

Implementation surfaces that must stay aligned with this addendum include `src/draft.js` main-stream promotion/refill rules, `src/quality-status.js` main item minimum/remediation text, `src/site.js`/`src/render.js` 12-item oversized semantics, `src/page-checklist.js`, candidate schema diagnostics, prompt modules, and automation revision strings such as `main_stream_blacklist_refill_5_to_12`.
