## Public Signal Stream Contract (Current Runtime Baseline)

Status: `implemented-runtime / target-superseded`.

The user changed the public product direction on 2026-07-14, and the repository still runs this high-coverage source listener at the 2026-07-15 baseline. Its lossless public membership rule is no longer the accepted target; it remains factual migration input until the phases and gates in the curated-edition specification pass.

- No content-admission gate exists in the public occurrence path. A safe HTTP(S) material URL is sufficient for membership; missing title text uses a deterministic publisher/source/URL fallback, while a structurally unsafe individual record is isolated without blocking the rest.
- Credibility, content, source, health, and access metadata are labels and filters only. Editorial score, authority, verification, selection, rejection, quality, quotas, dedupe, and report status cannot change membership or default chronology.
- Same-URL observations remain distinct occurrences and share a `cluster_id` only for navigation.
- Unknown source, content, and credibility metadata falls back to `other` / `pending_review` instead of failing, hiding, or demoting the record.
- Public fields are reader-safe title, link, summary, publisher, collection channel, source group, content tags, credibility tag, event/publication/collection time, image, health, and access state. Candidate IDs, raw audit, scores, selection/rejection reasons, repair state, notes, and private paths remain internal.
- `config/public-signal-taxonomy.json`, `schemas/occurrence-store.schema.json`, and `schemas/public-signals.schema.json` are the public data authorities. The immutable compressed occurrence baseline preserves the pre-PR2 public history without restoring runtime legacy reads. `config/source-display-contract.json` remains an internal source-inventory governance contract only.
- The landed PR1/PR2/PR3 work remains implementation evidence. Future migration must preserve its raw lineage, source coverage, privacy and atomic-build value while replacing the default public membership and IA.

The addenda below remain historical/current-runtime evidence. They are not the accepted target admission or IA rules after 2026-07-15.

## Story-Centered Contract Addendum (Historical Edited Report)

Status: `implemented / publish-run-validation-pending`.

The user confirmed on 2026-06-23 that the then-current edited-report target was story-centered, not raw source-item-centered. This remains implemented for that legacy derivative, but it was superseded as the controlling public product direction by the 2026-07-14 Public Signal Stream Contract.

- The main reader list is a set of edited, merged `stories`.
- Default story count is 8, maximum is 12, and fewer than 8 is acceptable when fewer qualified stories exist.
- The generator must not fill the main list with templated items such as `OpenAI更新AI 产品、平台或工程实践`.
- Strong primary single-source stories may enter the main list; secondary or community single-source items default to signal sections.
- Story merge and dedupe use factual identity and source URLs, not title or summary template similarity.
- Stories published in the previous 7 reports are excluded from the main list unless there is material new progress.
- GitHub Trending is a first-class fixed module: public Top10 items remain directly visible and are not folded into an appendix.
- Summary and trend clusters are derived from visible stories, GitHub Trending, or signal items, and must be able to link back to them.
- Quality gates should degrade by removing or demoting bad story candidates; they block only when publish artifacts are unusable, main stories are unverifiable, or publish safety fails.

The full contract, implementation surfaces, and staged TODO are in `docs/ai-daily-story-contract.md`. Schema, draft generation, report writing, rendering, page checklist, and regression tests are implemented in this branch. Do not claim a specific daily publish succeeded unless that date's run summary also proves `publish:dry-run:daily`, real publish or fallback, Pages verification, and blocking/degraded status.
