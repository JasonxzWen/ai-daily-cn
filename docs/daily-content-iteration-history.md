# 日报内容迭代历史

## 2026-06-08

### 目标

- 把日报从“工程师内部工作日志”拉回到“对外可读的内容/产品型长日报”。
- 优先处理信息质量，而不是继续为了凑数量保留低价值新闻。

### 本轮改动

- 主新闻改为 `3-5` 条公开要点，不再写“变化 / 落点 / 为什么重要”。
- `hot_blogs` 的公开标题统一改成“热门博客”。
- X/Twitter 原文清洗掉点赞、回复数、图片占位和按钮文案。
- `community_leads` 新增稳定标题，并收紧为更短、更像新闻流的摘要。
- OpenRouter、Artificial Analysis 允许在公开卡片里展示更多证据图。
- 新增候选过滤：
  - 过滤未来日期、OpenAlex/Zenodo/DOI 复现实验包、resolved status page。
  - 过滤中文/英文不可读标题。
  - 限制低信号 vendor partnership 在主新闻中的占比。
- 严格数量门改为“候选足够时才要求补满”，避免为了过门槛硬塞垃圾内容。

### 为什么这样改

- 用户关注的是“今天真正值得看什么”，不是抓取系统今天跑了多少条。
- 当前最大问题不是少一两个板块，而是主线被公关稿、外语索引页和机器腔占满。
- 如果候选本身不够好，继续按固定数量硬凑，只会反复生成低质量日报。

  - Builder 原文清洗
  - 低信号社区线索过滤
  - 低信号 partnership 主线限流
  - 候选不足时 strict minimum 不误报
- `tests/e2e/site.e2e.js`
  - 社区线索与 Builder 卡片 fixture 对齐新公开合同

## 后续优先项

- 持续补可读、可解释、非纯工程向的热门博客来源。
- 社区线索继续往“单行新闻流”压缩，减少大卡片感。
- 继续清掉旧 prompt、旧 fixture、旧历史产物里残留的“技不止术”“为什么重要”等旧口径。
