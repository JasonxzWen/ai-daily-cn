# 日报内容 Good / Bad Cases

## Good Cases

### 主新闻

- 有明确实体、动作和边界。
- 用 `3-5` 条说清楚事实、范围、影响，不写空判断。
- 同类新闻只保留最有信息密度的一条，不让同一家公司连续霸榜。

示例：

> **OpenAI 企业 API 更新**：新增可审计的任务接口和权限边界。
> **范围**：先看入口、价格、配额、可用地区和团队权限。
> **影响**：会直接影响试用顺序、接入成本和迁移计划。

### 热门博客

- 标题可读，最好是中文或英文。
- 摘要像“帮你看完了这篇文章”，不是“这篇文章很重要”。
- 优先收录工程、产品、agent、评测、内容工作流这类能落到使用场景的长文。

示例：

> 文章拆解了模型路由的三个真实约束：价格、延迟和失败率会互相拉扯。
> 作者给了企业实践里的演进路径，不只是讲概念。
> 适合用来判断该不该做多模型路由，而不是继续迷信单榜单。

### X / Builder 观察

- 保留原帖原文和完整中文翻译。
- 只收录真的在讲产品、工程、agent、评测或团队实践的帖子。
- 去掉 likes、replies、图片占位、按钮文案。

### 社区线索

- 一条就是一条新闻，不写成长段作文。
- 能有标题、摘要、来源、日期和图片最好。
- 可以是中介线索，但要对读者有用，而不是“这里有个链接你自己看”。

## Bad Cases

### 主新闻坏例子

- “变化：xxx。落点：xxx。为什么重要：xxx。”
- 同一天放 4 条 NVIDIA partnership / AI factory 公关稿。
- 用外语索引页或乱码标题硬顶主线。

### 热门博客坏例子

- 标题不可读，像泰语、越南语索引页直接进正文。
- 摘要全是“值得关注”“说明趋势”“读者可重点看”。
- 明明没有高质量博客，还硬凑 3 条。

### X / Builder 坏例子

- 原文里混入 `123 Likes`、`5 Replies`、`View post image`。
- 把原帖翻成一句泛泛总结，丢掉原意。
- 收录“good night”“touch sand”这类跟 AI 工作流无关的内容。

### 社区线索坏例子

- 未来日期的 OpenAlex / Zenodo / DOI 复现实验包。
- 已经 `Resolved` 的 status page 事故。
- 和 AI 无关的娱乐、体育、通用前端内容。

## 出手顺序

1. 先删垃圾，再补数量。
2. 先保证标题可读，再优化文案。
3. 先保证一手或高信号来源，再考虑视觉丰富度。
4. 候选不够时宁可降级披露，也不要拿低质量内容补齐。
