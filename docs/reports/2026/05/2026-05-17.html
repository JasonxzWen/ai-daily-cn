ThreatConnect 8.0 发布 Agentic Threat Intelligence Platform

2026-05-16T0ThreatConnectAgentic AIThreat IntelligenceSTRIDEPlaybooks
  • 四个代理都围绕已有 ThreatConnect 情报和 workflow 数据工作，官方说明它们基于 playbook architecture，并在 LLM reasoning layer 之外接入实例内情报和流程数据。
  • ThreatConnect Query Agent 会给出 source links 供继续核验；STRIDE Threat Modeling Agent 可从 Ask AI 或 Threat Actor Profile 详情页生成结构化报告。
  • 8.0 同时加入 Playbook Routes 和 Parameter Sets，用更少节点表达分支逻辑并复用 app 参数，这说明安全运营平台的 AI 功能正和既有自动化编排层绑定，而不是只做一个聊天侧栏。

AWS Partner Central agents 支持用自然语言创建机会并提供 MCP 入口

2026-05-15T0AWSAWS Partner CentralAmazon Bedrock AgentCoreAmazon QMCP
  • 合作伙伴可以用自然语言描述交易、上传 meeting notes、proposals、call transcripts，或 clone 现有 opportunity；代理会抽取信息、补充 customer details 并建议修正缺失上下文或字段。
  • 入口同时覆盖 AWS Console 中的 Amazon Q chat 和可编程 Model Context Protocol，因此销售团队可以从既有工具中触发机会创建，而不是只能进入 AWS Console 表单。
  • 该功能已在所有 commercial AWS Regions 提供，说明 Bedrock AgentCore 正被 AWS 用于内部/伙伴业务流程，而不仅是通用 agent 开发样例。

来源：AWS What's New

Firecrawl v2.10 合并发布 parse、Lockdown、Question/Highlights 和新 SDK

2026-05-15T0Firecrawlv2.10ParseLockdown ModeMCP
  • `/parse` 可把 PDF、Word、spreadsheet 等文件转成 LLM-ready Markdown、JSON 或 summary，并标注文件上限为 50 MB，适合 RAG ingestion 和 agent 文档读取。
  • Lockdown Mode 允许 `/scrape` 只从 Firecrawl index 返回结果，不发起 outbound requests，并默认 zero data retention；该能力覆盖 API、CLI 和 MCP。
  • Question 和 Highlights format 的重点是上下文压缩：前者返回 page-grounded answer，后者返回匹配 query 的原句、代码块和表格行；对 agent loop 来说，这是把网页读取从“整页塞上下文”改成可控提取。

来源：Firecrawl Changelog

xAI 发布 Grok Build 终端 coding agent early beta

2026-05-14T0xAIGrok BuildCoding agentCLIMCP
  • Grok Build 支持 plan mode：复杂任务先生成计划，用户可批准、评论单步或重写计划；批准后变更以 clean diff 方式展示。
  • 官方页面明确 AGENTS.md、plugins、hooks、skills 和 MCP servers 可直接工作，说明 xAI 选择兼容现有 agent repo 约定，而不是要求用户迁移到全新项目格式。
  • 页面还展示 parallel subagents、worktree integrations、headless mode `-p` 和 ACP support；这使它更像一个可脚本化 agent harness，而不仅是交互式 CLI。

来源：xAI News

OpenAI 披露 ChatGPT 在敏感对话中的上下文安全更新

2026-05-14T0OpenAIChatGPTSafety summariesGPT-5.5 InstantSensitive conversations
  • 该工作聚焦 suicide、self-harm 和 harm-to-others 场景；OpenAI 称 safety summaries 不是通用 personalization 或 long-term memory，而是窄范围、限时、只在严重安全担忧相关时使用。
  • OpenAI 公布的内部评估显示，长单轮对话中 suicide/self-harm 场景 intended safe response 提升 50%，harm-to-others 提升 16%；在 GPT-5.5 Instant 上，跨多对话 harm-to-others 提升 52%，suicide/self-harm 提升 39%。
  • 对构建面向高风险对话的产品团队来说，关键变化是 safety state 成为运行时上下文的一部分；这会影响日志保留、风险升级、用户透明度和普通对话误触发评估。

来源：OpenAI
