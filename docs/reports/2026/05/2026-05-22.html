提示词与规则迭代建议

  1. GitHub Trending 仓库命令受 shell 网络限制时只能人工浏览器复核

    模块：discovery-audit需要确认

    证据：`npm run discover:github-trending -- 50` 返回 fetch failed，但浏览器能访问 GitHub Trending 页面并抽取候选。

    建议：为 discovery 命令增加可选的 browser-export 输入路径，允许自动化把浏览器采样结果或保存的 HTML 交给同一解析器处理。

    预期收益：减少 shell 网络限制导致的 source_audit 断裂，让 GitHub Trending 候选仍可结构化复用。

  2. Builder feed 不可访问时只能记录 blocked，无法区分临时网络错误和中心 feed 真实无内容

    模块：builder-observations需要确认

    证据：follow-builders prepare-digest.js 本轮返回 fetch failed，X status 页面直接打开为空 HTML。

    建议：为 Builder 来源增加 `blocked_reason` 和 `last_successful_feed_at` 字段，避免只在 notes 中描述失败状态。

    预期收益：让日报读者和后续自动化能判断 Builder 观察为空是网络问题还是确实没有合格原始源。

  3. 模型发布与网关接入容易混在同一条事实中

    模块：model-releases需要确认

    证据：Qwen 3.7 Max 本轮只能用 Vercel 官方网关可用性作为一手来源，二手媒体包含 Alibaba 发布细节但未进入主事实。

    建议：在 model_releases 中增加 `release_scope`，区分 provider official launch、gateway availability、preview access 和 model card update。

    预期收益：减少把第三方网关接入误写成模型厂商正式发布的风险。
