提示词与规则迭代建议

  1. 聚合型主体条目仍只有单一 url 字段，Google I/O 与 GitHub Copilot 这类同日多子发布只能挂总页或代表页。

    证据：本轮 Google I/O 开发者栈涉及 Gemini 3.5、Managed Agents、Antigravity、AI Studio；GitHub Copilot 涉及 Gemini 3.5 Flash 和 Fix with Copilot。单 URL 会丢失部分子页面证据。

    预期收益：为 main_items 增加 optional related_urls 后，可以合并同厂商动态同时保留可审计子链接。

  2. model_releases 只能用单一 availability 表达可用性，难以描述同一模型同时进入 API、产品和第三方平台。

    证据：Gemini 3.5 Flash 同时出现在 Gemini app、AI Mode、Antigravity、Gemini API、AI Studio、GitHub Copilot 和企业平台；当前只能选 closed_api 并把其余信息塞进 notes。

    预期收益：增加 platforms 或 availability_notes 字段后，模型区块会更适合跟踪跨产品/跨平台发布。

  3. 社区线索没有结构化状态字段，导致 Mistral 3 这类“内容可信但日期证据不足”的项目只能写在自然语言里。

    证据：Mistral 3 官方页有完整模型信息和可用路径，但本轮没有稳定 published date；需要表达为 date_unverified，而不是普通 community lead。

    预期收益：给 community_leads 增加 status/reason，可让后续自动复核更稳定，并减少旧闻误入主体。
