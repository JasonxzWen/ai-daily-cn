# Daily Publish Task Template

## Goal

Generate, validate, dry-run, and publish the Chinese AI daily report for `YYYY-MM-DD`.

## Runner

- Start from the launcher worktree with `npm run daily:run -- --date YYYY-MM-DD`.
- Use `npm run daily:run -- --date YYYY-MM-DD --publish` only when real publish is explicitly allowed.
- Read `.tmp/run-summary-YYYY-MM-DD.json` for `final_status` and `next_action`.
- If `next_action.kind` is `codex_ai_repair_contract`, write the requested contract with `status:"ready"` and non-empty `edits`, then resume with the same `daily:run` command. If the runner provided a `status:"template"` file, fill edits in that new attempt file instead of overwriting prior attempts.
- Use `--restart` only when intentionally discarding same-date runner state.
- Scheduled dry-run uses `publish:dry-run:daily`.
- 21:30 status self-check uses `npm run status:self-check -- --date YYYY-MM-DD --output .tmp/status-self-check-YYYY-MM-DD.json` and treats `multiple_active_daily_publish_automations` as blocking.

## Assumptions

- Date is interpreted in `Asia/Shanghai`.
- 唯一权威资产是 `prompts/ai-daily/modules/editorial-authority.md`；若与旧规范、旧 ROI 清单或旧 prompt 口径冲突，以该文件为准。
- Existing project instructions in `AGENTS.md` remain authoritative.
- Real publish requires explicit confirmation.

## Non-goals

- Do not change GitHub Pages settings.
- Do not modify automation config unless explicitly requested.
- Do not force push, reset, stash, or overwrite unrelated user work.
- Do not hand-write the production daily HTML.

## Worktree / Branch

- Record `git status --short --branch`.
- Automation and publish runs start from the launcher worktree by invoking `daily:run`; the runner prepares and uses the clean publish checkout internally.
- Use `npm run publish:prepare-clean-worktree` only for manual checkout diagnostics.
- Record whether the run is local generation only, dry-run only, or real publish.

## Allowed paths

- `.tmp/**`
- `reports-data/YYYY/MM/YYYY-MM-DD.json`
- `reports-data/YYYY/MM/YYYY-MM-DD.candidates.json`
- `docs/**` generated by `npm run build`
- `progress.md` for human-assisted runs only
- `session-handoff.md` for human-assisted runs only

## Forbidden paths

- `.github/**`
- `config/**`
- `prompts/**` unless the user explicitly approves prompt changes.
- `src/**` unless the task is a code fix, not a daily publish run.
- Remote Pages settings and automation configuration.

## Acceptance criteria

- Candidate pool and structured draft pass report-write gates.
- All collected information is compared against recent `reports-data` reports/candidate pools and deduped before selection.
- Runner records `sources:phase5-audit` before dry-run/publish completion.
- If prompt / rule changes are explicitly approved during the run, update `prompts/ai-daily/modules/editorial-authority.md` together with its `本轮修改清单`、`Good Case`、`Bad Case`、`迭代历史`.
- `npm run validate` passes.
- `npm run publish:dry-run:daily -- --date YYYY-MM-DD` reports the date-scoped publish plan and expected Pages URL.
- Real publish, when approved, verifies the final Pages URL.

## Validation commands

- `node scripts/harness-validate.mjs`
- `npm run report:write -- .tmp/daily-report.json reports-data YYYY-MM-DD`
- `npm run build`
- `npm run validate`
- `npm run publish:dry-run:daily -- --date YYYY-MM-DD`

## Parallel writes

- Default: blocked for publish runs.
- Read-only source discovery can be parallelized when outputs are merged into one candidate pool.

## Handoff requirements

- Human-assisted runs update `progress.md` and `session-handoff.md`.
- Scheduled automation runs do not modify or commit `progress.md`, `session-handoff.md`, or `tasks/current-task.md`.
- Include publish status, Pages URL, validation result, and unresolved blockers.
